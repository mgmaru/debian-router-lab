## 疑問

[ip-address.md](../concepts/ip-address.md#255255255255限定ブロードキャスト) に、次のように書いてある。

> DHCP の最初の呼びかけ（Discover）は `255.255.255.255` 宛てです。IP アドレスをもらう前の機器は、自分がどのネットワークにいるのかを知らないので、`10.0.0.255` を計算できないからです。

> **質問28**：たとえば新しい機器があるネットワークに組み込まれたとき、その機器は一番初めに `255.255.255.255` に問い合わせて、DHCP からアドレスをもらうのか？

> **質問29**：これは初回だけで、ネットワークが分かった時点で、次に DHCP に問い合わせるときは `10.0.0.255` に問い合わせるのか？

## 結論

| 質問 | 答え |
|---|---|
| 最初は `255.255.255.255` に問い合わせる？ | **その通り。** DHCP を使う設定（`inet dhcp`）の機器は、つないだら最初に `255.255.255.255` 宛てに「IP をください」（Discover）と呼びかける。まだ IP アドレスを持っていないので、送信元は `0.0.0.0` になる |
| 2 回目からは `10.0.0.255` に問い合わせる？ | **違う。DHCP が `10.0.0.255` を使うことはない。** 2 回目以降は、**DHCP サーバーの IP アドレスに直接**問い合わせる（ユニキャスト）。全員宛てに送る場面も残っているが、そのときも `255.255.255.255` を使う |

## 質問28：最初は `255.255.255.255` に問い合わせるのか

### 結論

**その通り。** 新しい機器をつなぐと、まず `255.255.255.255` 宛てに呼びかけるところから始まる。

### 最初のやりとり（DORA）

```text
新しい機器（IP なし）                            DHCP サーバー
  │ ① Discover：送信元 0.0.0.0 → 宛先 255.255.255.255
  │   「誰か IP をください」
  │ ──────────────────────────────────────────▶
  │ ② Offer「10.0.0.100 はどう？」
  │ ◀──────────────────────────────────────────
  │ ③ Request：送信元 0.0.0.0 → 宛先 255.255.255.255
  │   「10.0.0.100 をもらいます」
  │ ──────────────────────────────────────────▶
  │ ④ Ack「どうぞ。期限は 30 分」
  │ ◀──────────────────────────────────────────
  ▼
10.0.0.100/24 を使い始める
```

（`10.0.0.100` は説明用の例。LAN 側にはまだ DHCP サーバーがいない）

| ステップ | 送信元 | 宛先 | ポイント |
|---|---|---|---|
| ① Discover | `0.0.0.0` | `255.255.255.255` | まだ IP が無いので、送信元は `0.0.0.0`。DHCP サーバーのアドレスも、自分のネットワークも分からないので、全員宛て |
| ③ Request | `0.0.0.0` | `255.255.255.255` | まだ IP を正式にもらっていないので、送信元は `0.0.0.0` のまま。DHCP サーバーが複数いた場合に、「このサーバーの提案を選んだ」とほかのサーバーにも知らせる役目もある |

IP アドレスが無い機器を、サーバーはどうやって見分けるのか。それは、メッセージの中に書かれた **MAC アドレス**で見分けている（[DHCP サーバーはどう作るのか](2026-10-12-how-to-implement-dhcp-server.md)）。

> 💡 サーバーからの返事（② Offer と ④ Ack）は、全員宛てで返すことも、配る IP へ直接返すこともある。どちらになるかは、クライアントが付けた印などで決まる（[どこへ返すか](2026-10-12-how-to-implement-dhcp-server.md#どこへ返すかrfc-2131-の決まり)）。

### 呼びかけるのは、DHCP を使う機器だけ

| 機器の設定 | つないだときの動き |
|---|---|
| `inet dhcp`（Router VM の ens33） | `255.255.255.255` 宛てに Discover を送る |
| `inet static`（Router VM の ens37、Client VM） | DHCP は使わない。設定ファイルに書いた IP をそのまま使う |

DHCP で呼びかけても、誰も答えなかった場合はどうなるか。そのときは `169.254.x.x` のリンクローカルアドレスが付く。labs/01 で Client VM に起きたのはこれである（[interface.md](../concepts/interface.md#リンクローカルアドレス169254xx)）。

## 質問29：2 回目からは `10.0.0.255` に問い合わせるのか

### 結論

**違う。DHCP が `10.0.0.255` を使うことはない。**

2 回目以降は、**DHCP サーバーの IP アドレスに直接**問い合わせる。全員宛てに送る場面も残っているが、そのときも `255.255.255.255` を使う。

### 2 回目以降は、リースの延長

DHCP でもらった IP には期限（リース）がある。機器は期限が切れる前に、DHCP サーバーへ延長を申し込む。

最初の Ack には、DHCP サーバーのアドレス（オプション 54）が書いてある。そのため 2 回目からは、**相手が分かっている。** 相手が分かっていれば、全員に送る必要はない。

Router VM の ens33 の場合、リースは 30 分（1,800 秒）、DHCP サーバーは `192.168.22.254` である（[質問8](2026-10-11-where-to-find-dhcp-server-address.md)）。

| いつ | 何をする | 宛先 |
|---|---|---|
| 半分（900 秒）が過ぎたとき | **延長**：「引き続き使わせて」 | **DHCP サーバーに直接**（`192.168.22.254`） |
| 87.5%（1,575 秒）が過ぎても延長できないとき | **再取得**：「どのサーバーでもいいので延ばして」 | `255.255.255.255` |
| 期限が切れたとき | IP を手放して、Discover からやり直す | `255.255.255.255` |
| 再起動したとき | 「前の IP をまた使いたい」 | `255.255.255.255` |

ふだんは、いちばん上の**延長**で済む。

前に `sudo dhcpcd -U ens33` を実行したとき、`reason=RENEW` と表示された。これは、900 秒のときの延長（サーバーへの直接の問い合わせ）が成功していた、という意味である。

### なぜ `10.0.0.255` を使わないのか

ネットワークが分かったあとでも、DHCP が `10.0.0.255` を使う場面はない。理由は 2 つある。

**理由 1：相手が分かっているなら、直接送るほうがよい**

延長のときは、サーバーの IP が分かっている。全員宛てに送ると、関係のない機器にも届いて、手間をかけさせてしまう。サーバーに直接送れば、ほかの機器には届かない。

**理由 2：全員に送るのは「何かが不確か」なときだけ。そのときは、前の情報を信用できない**

全員宛てが残っている場面は、どれも状況が不確かなときである。

| 場面 | 何が不確かか |
|---|---|
| 再起動 | 前と同じネットワークにいるか分からない。たとえば、ノート PC を会社から家に持って帰ったかもしれない |
| 再取得 | 前の DHCP サーバーが応答しない。いなくなったのかもしれない |
| 期限切れ | もう IP を手放しているので、最初の状態と同じ |

前の情報から計算した `10.0.0.255` は、別のネットワークに移っていれば、間違った宛先になる。`255.255.255.255` なら、**どのネットワークにいても、今つながっているケーブルの全員に必ず届く。** そのため、DHCP クライアントは全員宛てに送るとき、いつも `255.255.255.255` を使う。

> 💡 同じネットワークの中なら、`10.0.0.255` 宛ても `255.255.255.255` 宛ても、届く相手は同じである。わざわざ `10.0.0.255` を計算する利点がない。

### まとめると

| 場面 | 宛先 |
|---|---|
| 初めてつないだとき（Discover、Request） | `255.255.255.255` |
| 延長（ふだんはこれ） | **DHCP サーバーに直接** |
| 再取得・期限切れ・再起動 | `255.255.255.255` |
| `10.0.0.255` | **DHCP では使わない** |

## まとめ

- DHCP を使う機器は、つないだら最初に `255.255.255.255` 宛てに Discover を送る。まだ IP が無いので、送信元は `0.0.0.0`。続く Request も同じく全員宛て。
- 2 回目以降は、**DHCP サーバーの IP に直接**延長を申し込む。最初の Ack で、サーバーのアドレスが分かっているから。
- 全員宛てが残るのは、再取得・期限切れ・再起動など、状況が不確かなときだけ。そのときも、どのネットワークにいても届く `255.255.255.255` を使う。
- **DHCP が `10.0.0.255` を使うことはない。**
