# 専用ルーターはなぜ仕事を 2 つに分けるのか：CPU と ASIC の違い

調査日：2026-10-24

## 疑問

> **質問48**：専用ルーターは、仕事を 2 つ（経路を決める役と、パケットを転送する役）に分けるとのことだが、OS に任せられない理由があるのか？

> **質問49（追加質問）**：①の「CPU では間に合わない」がよく分からない。そもそも処理は CPU で行うのだと思うが、どうか？ OS から CPU に処理を渡していると、速度が足りないということか？

## 結論

| 質問 | 答え |
|---|---|
| なぜ仕事を 2 つに分ける？ | 理由は 2 つ。**① 速さ**：大量のパケットの転送は、CPU では間に合わない。**② 止まらないこと**：経路の計算などで CPU が忙しくなっても、転送を止めないため |
| OS に任せられない？ | **OS が不要なわけではない。** 経路の計算や設定は OS の上のソフトウェアが担当し、転送だけを専用チップに任せる。「向いている仕事を、向いている部品にさせる」分け方である |
| 処理はすべて CPU で行うのでは？ | **専用ルーターでは、パケットの転送に CPU を使わない。** ASIC（専用チップ）は CPU とは**別のチップ**で、転送を自分で処理する。パケットは CPU を通らない |
| OS から CPU に渡すので遅い？ | **そうではない。** OS も CPU の上で動くプログラムなので、「OS から CPU に渡す」という関係は無い。遅いのは、CPU が「何でもできる代わりに、命令を 1 つずつ実行する」部品だからである |

---

## 前提：処理はすべて CPU で行うわけではない

コンピューターの中には、CPU 以外にも「処理をする部品」がある。

| 部品 | 得意なこと |
|---|---|
| **CPU** | 何でもできる。プログラム（命令の並び）を読んで、順番に実行する |
| **GPU** | 画像や AI の計算。同じ計算を、大量のデータに同時に行う |
| **ASIC**（特定用途向けの集積回路） | **決まった 1 つの仕事だけ**。その仕事の手順を、電子回路として作り込んである |

専用ルーターの ASIC は、「パケットを転送する」ことだけのために作られたチップである。パソコンで画像の処理を CPU ではなく GPU に任せるのと、似た考え方である。

### OS も CPU の上で動くプログラム

「OS から CPU に処理を渡す」という関係は無い。OS（Linux など）自体が、**CPU の上で動くプログラム**である。

```text
+-------------------------------------------+
| アプリケーション（ssh、ping など）        |
+-------------------------------------------+
| OS（Linux カーネル）                      |  ← これもプログラム
+-------------------------------------------+
| CPU                                       |  ← 上のプログラムを、すべて実行している
+-------------------------------------------+
```

labs/02 で「Linux が転送した」というのは、正確には「**CPU が、カーネルの中の転送用のプログラムを実行した**」という意味である。

## Linux と専用ルーターの、パケットの通り道

### Linux（このラボの Router VM）：すべてのパケットが CPU を通る

```text
  ens37（NIC）
     │ ① パケットを受け取り、メモリに書き込んで、CPU に知らせる
     ↓
  メモリ
     │
     ↓
  CPU（カーネルの転送用のプログラムを実行）
     │ ② ヘッダを読む
     │ ③ ルーティングテーブルを探す
     │ ④ TTL を減らし、チェックサムを計算し直す
     │ ⑤ MAC アドレスを付け替える
     ↓
  メモリ
     │ ⑥ 送り出す NIC に渡す
     ↓
  ens33（NIC）
```

### 専用ルーター：パケットは CPU を通らない

```text
                    +----------------------------------+
                    | CPU ＋ OS（コントロールプレーン）|
                    |  ・他のルーターと経路の情報交換  |
                    |  ・ルーティングテーブルの計算    |
                    |  ・設定、SSH ログイン            |
                    +----------------------------------+
                                  │ 計算した表を書き込む
                                  ↓
  ポート 1 ──→ +----------------------------------+ ──→ ポート 2
  ポート 3 ──→ | ASIC（データプレーン）           | ──→ ポート 4
     ...       |  表を引く → TTL → MAC → 送り出す |      ...
               +----------------------------------+
                    ↑ パケットはここだけを通る
```

| 名前 | 担当する仕事 | 処理する部品 |
|---|---|---|
| **コントロールプレーン** | 経路を決める（ルーティングテーブルを作る）、設定を受け付ける | CPU ＋ OS ＋ ソフトウェア |
| **データプレーン** | 作った表に従って、1 つ 1 つのパケットを転送する | ASIC（専用チップ） |

## 質問49：なぜ CPU では間に合わないのか

### CPU は「何でもできる」代わりに、命令を 1 つずつ実行する

CPU は、足し算・比較・メモリの読み書きといった**小さな命令**を、順番に実行していく。パケットを 1 つ転送するだけでも、上の図の①〜⑥の作業があり、命令は**数百〜数千個**になる。

### ASIC は「転送しかできない」代わりに、回路そのものが処理する

ASIC は、転送の手順を**電子回路として作り込んだ**チップである。命令を読んで実行するのではなく、パケットが回路を流れるだけで処理が終わる。さらに、多くのパケットを**同時に**流せる。

ルーティングテーブルの検索にも、専用の部品を使う。

| | CPU | ASIC |
|---|---|---|
| ルーティングテーブルの検索 | メモリ上の表を、順番にたどっていく | **TCAM** という専用のメモリで、表全体を**一度に**照合する |

### たとえ

```text
CPU：何でも作れる料理人
  レシピを読む → 材料を切る → 焼く → 盛り付ける → 次の 1 皿へ
  どんな料理でも作れるが、1 皿ずつ作るので数には限りがある

ASIC：1 種類の製品だけを作る工場の生産ライン
  材料を流すと、製品が次々に出てくる
  ほかの物は作れないが、圧倒的に速い
```

転送の手順（表を引く → TTL を減らす → MAC を付け替える → 送り出す）は、**単純で、ひたすら繰り返す**仕事である。そのため、生産ライン（ASIC）に向いている。

### 数字で見ると

100Gbps のポート 1 本に、いちばん小さいパケット（64 バイト）が流れ続けると、**1 秒間に約 1 億 5000 万個**になる。

```text
CPU コア 1 つ（3GHz）の 1 秒間のクロック数   ：  30 億
100Gbps で届くパケットの数（1 秒間）         ：   1 億 5000 万個
                                                ─────────────────
1 パケットに使えるクロック数                  ：  約 20
```

| | 1 パケットに必要な量 | 1 パケットに使える量 |
|---|---|---|
| CPU で転送する場合 | 数百〜数千の命令 | 約 20 クロック |

**必要な量に、まったく足りない。** 大きなルーターはこうしたポートを何十本も持っているので、CPU だけで転送するのは到底無理である。

目安として、Linux カーネルの通常の転送は、CPU コア 1 つで 1 秒間に数百万個くらいである。

### 小さなルーターなら CPU で十分

家庭や小さな拠点の通信量（1Gbps 程度）なら、CPU でも十分に間に合う。このラボの Router VM が、カーネル（CPU）だけで転送できているのはそのためである。

| ルーター | 通信量 | 転送する部品 |
|---|---|---|
| このラボの Router VM | 小さい | CPU（Linux カーネル） |
| 家庭用ルーター | 〜数 Gbps | 主に CPU（転送を助ける専用の回路を持つものもある） |
| 企業の拠点ルーター | 数 Gbps〜 | 機種による |
| データセンターや通信事業者の大型ルーター | 数 Tbps | ASIC |

## 質問48：なぜ仕事を 2 つに分けるのか

### 理由 ① 速さ

上の質問49 のとおり、大量のパケットの転送は CPU では間に合わない。転送だけを ASIC に任せる。

### 理由 ② 止まらないこと

コントロールプレーンの仕事は、重くなることがある。

- 他のルーターと経路の情報を交換し（BGP、OSPF などのルーティングプロトコル）、表を計算し直す
- 管理者の SSH ログインや、設定の変更を受け付ける
- ルーター自身を狙った攻撃のパケットを受ける

もし同じ CPU で転送もしていたら、**CPU が忙しいときに、転送まで遅くなったり止まったりする**。

```text
分けていない場合
  CPU：[経路の計算][経路の計算][転送][経路の計算][転送]...  ← 転送が待たされる

分けている場合
  CPU ：[経路の計算][経路の計算][SSH][経路の計算]...
  ASIC：[転送][転送][転送][転送][転送][転送][転送]...      ← 今ある表で転送を続ける
```

役割を分けておけば、コントロールプレーンが忙しくても、データプレーンは今ある表に従って転送を続けられる。

### OS が不要なわけではない

専用ルーターにも OS はある。Cisco の IOS XE や Juniper の Junos のように、中身が Linux や FreeBSD のものも多い。

| 仕事の性質 | 担当 |
|---|---|
| 複雑で、変化に対応する必要がある（経路の計算、設定、ログイン） | **CPU ＋ OS**（ソフトウェアは、作り変えやすい） |
| 単純で、大量に繰り返す（パケットの転送） | **ASIC**（回路は作り変えられないが、圧倒的に速い） |

つまり、「OS に任せられない」というより、「**OS には向いている仕事を、チップには向いている仕事をさせる**」という分け方である。

### Linux にも、転送を速くする仕組みがある

| 仕組み | 内容 |
|---|---|
| **XDP** | パケットを、カーネルの通常の処理より手前で処理する |
| **DPDK** | カーネルを通さず、プログラムが NIC から直接パケットを受け取る |
| **NIC へのオフロード** | 一部の処理を、NIC のチップに任せる |

どれも、「CPU が 1 パケットにかける手間を減らす」か、「処理を CPU 以外に任せる」ための工夫である。

## まとめ

- 専用ルーターは、仕事を**コントロールプレーン**（経路を決める。CPU ＋ OS）と**データプレーン**（パケットを転送する。ASIC）に分ける。
- **処理はすべて CPU で行うわけではない。** ASIC は CPU とは別のチップで、転送を自分で処理する。専用ルーターでは、パケットは CPU を通らない。
- **OS も CPU の上で動くプログラム**なので、「OS から CPU に渡すから遅い」のではない。CPU は何でもできる代わりに、命令を 1 つずつ実行するので、大量のパケットには間に合わない。
- 100Gbps のポートでは、1 パケットに使えるのは CPU の約 20 クロックだけで、転送に必要な数百〜数千の命令には足りない。
- 仕事を分けるもう 1 つの理由は、**CPU が忙しくても転送を止めないため**である。
- 家庭や小さな拠点の通信量なら、CPU（Linux カーネル）でも十分に転送できる。このラボの Router VM もそうである。
