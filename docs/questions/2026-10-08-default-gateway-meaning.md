# デフォルトゲートウェイとは「同じネットワークで転送先が見つからない場合の送り先」か

調査日：2026-10-08

関連：[docs/concepts/routing.md（デフォルトゲートウェイ）](../concepts/routing.md#デフォルトゲートウェイ)

## 疑問

> デフォルトゲートウェイの説明について、「同じネットワークで転送先が見つからない場合に、パケットを送る宛先」という理解で良いか？

## 結論

**大筋は合っている。ただし、2 点直すとより正確になる。**

> デフォルトゲートウェイとは、**宛先が、自分の知っているどのネットワークにも当てはまらないときに、パケットを託す次の中継先（ルーター）**である。

| 元の理解 | 直したほうがよい点 |
|---|---|
| 同じネットワークで**見つからない**場合 | 探してから決めるのではなく、送る前に**ルーティングテーブルと照らし合わせて**決める |
| パケットを送る**宛先** | パケットの宛先は変わらない。ゲートウェイは**ひとまず手渡す相手** |

---

## 直す点 1：「見つからなかったら」ではなく「当てはまらなかったら」

端末は、相手を探しに行ってから送り方を決めるのではない。**送る前に、宛先 IP をルーティングテーブルと照らし合わせて決める。**

Client VM のルーティングテーブルは、おおよそ次のようになる（`ip route` の出力例）。

```text
default via 10.0.0.1 dev ens33                    ← どれにも当てはまらない宛先
10.0.0.0/24 dev ens33 proto kernel scope link ... ← 自分のネットワーク（直接届く）
```

| 宛先 | 当てはまる経路 | 動き |
|---|---|---|
| `10.0.0.1` | `10.0.0.0/24` | 直接送る |
| `10.0.0.99`（存在しない機器） | `10.0.0.0/24` | 直接送ろうとして失敗する。**ゲートウェイには回さない** |
| `8.8.8.8` | `default` だけ | `10.0.0.1` に託す |

`10.0.0.99` の行がポイントである。「同じネットワークで見つからない場合」と覚えると、同じネットワーク内で見つからなければゲートウェイに回すように読めてしまう。
実際には、自分のネットワークの範囲内の宛先なら、見つからなくても `Destination Host Unreachable` で終わる。

---

## 直す点 2：「宛先」ではなく「渡す相手」

ゲートウェイに渡すときも、**パケットの宛先 IP は `8.8.8.8` のまま変わらない。** 変わるのは、LAN の中で「まず誰に手渡すか」（宛先 MAC アドレス）だけである。

```text
IP の宛先  ：8.8.8.8               ← 最終的な宛先（変わらない）
MAC の宛先 ：ルーター VM の ens37   ← ひとまず手渡す相手
```

`ip route` の `via`（〜を経由して）という表記も、この「経由する相手」を表している。

---

## 検証：`ip route get` で判断の結果を見る

`ip route get <宛先>` は、「その宛先へパケットを送るとしたら、どう送るか」をカーネルに問い合わせるコマンドである。**実際にパケットを送るわけではない。**

### Client VM での実行結果

**① ネットワークの外（`8.8.8.8`）**

```text
kajih@debian-client:~$ ip route get 8.8.8.8
8.8.8.8 via 10.0.0.1 dev ens33 src 10.0.0.10 uid 1000
    cache
```

**② 自分のネットワーク内（`10.0.0.1`）**

```text
kajih@debian-client:~$ ip route get 10.0.0.1
10.0.0.1 dev ens33 src 10.0.0.10 uid 1000
    cache
```

### 出力の読み方

①を一文に訳すと：

> `8.8.8.8` 宛てのパケットは、**ens33 から**出して、**10.0.0.1 に託す**。送信元の IP には **10.0.0.10** を使う。

| 表示 | 意味 | ①の値から分かること |
|---|---|---|
| `8.8.8.8` | 問い合わせた宛先 | — |
| `via 10.0.0.1` | **次に渡す相手（ゲートウェイ）** | 直接は届かないので、ルーター VM に託す |
| `dev ens33` | パケットを出すインターフェース | Client VM の唯一の NIC から出る |
| `src 10.0.0.10` | 送信元として使う自分の IP | ens33 に付いている自分のアドレス |
| `uid 1000` | 問い合わせたユーザーの ID | `kajih` のこと。Debian では最初に作った一般ユーザーが 1000 になる（`id` コマンドで確認できる）。普段は気にしなくてよい |
| `cache` | ルーティングテーブルそのものではなく、問い合わせに対して計算した結果であるという印 | 普段は気にしなくてよい。通信の状況によっては `mtu` などの情報が付くことがある |

最初の 4 つ（宛先・`via`・`dev`・`src`）を読めれば十分である。

### ①と②の比較

| | ① `8.8.8.8` | ② `10.0.0.1` |
|---|---|---|
| `via` | `via 10.0.0.1` **あり** | **無し** |
| 意味 | ルーター VM に託す | 相手に直接届ける |
| 使われた経路 | `default via 10.0.0.1 dev ens33` | `10.0.0.0/24 dev ens33` |
| 理由 | `10.0.0.0/24` の範囲外 | `10.0.0.0/24` の範囲内 |

**出力に `via` があるかどうかで、そのパケットがゲートウェイを通るかどうかを見分けられる。**

`dev ens33` と `src 10.0.0.10` は、出ていく NIC が 1 つしかないため、どちらも同じになる。

> 💡 `10.0.0.1` は、たまたまゲートウェイと同じ機器である。それでも、宛先が自分のネットワーク内なら、**「ゲートウェイとして」ではなく「普通の相手として」直接届ける**。

## まだ試していないこと

| コマンド（Client VM） | 予想される結果 | 確かめられること |
|---|---|---|
| `ping -c 2 10.0.0.99` | `Destination Host Unreachable` | 範囲内の宛先は、見つからなくてもゲートウェイに回らない（直す点 1） |
| `ip neigh` | `10.0.0.1` に対応する MAC アドレス（`lladdr 00:0c:29:...`） | ゲートウェイに手渡すときの宛先 MAC（直す点 2） |

---

## まとめ

- デフォルトゲートウェイは、**どの経路にも当てはまらない宛先のパケットを託す次の中継先**。
- 判断は「探してみて見つからなかったら」ではなく、**送る前にルーティングテーブルで決まる**。
- ゲートウェイに渡しても**宛先 IP は変わらない**。変わるのは手渡す相手（MAC）だけ。
- `ip route get <宛先>` の出力に **`via` があればゲートウェイ経由、無ければ直接**。
