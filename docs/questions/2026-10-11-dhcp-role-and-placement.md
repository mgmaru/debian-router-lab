## 結論

| 質問 | 答え |
|---|---|
| DHCP はルーターの機能か？ | **厳密には違う。** ルーターの本来の仕事は「パケットを別のネットワークへ中継すること」。DHCP は「機器に設定を配る**サーバー**」で、別のネットワークサービスである。家庭用ルーターが 1 台にまとめて載せているので、ルーターの機能に見える |
| NAT の一部か？ | **違う。** NAT は「中継するパケットのアドレスを書き換える」機能。DHCP とは協力するが、別々に使える |
| どこに置くか？ | **ローカル**（DHCP で設定をもらう機器と同じネットワーク）。インターネット上には置けない。最初の呼びかけがブロードキャストで、ルーターを越えられないから |
| ルーターとは別物で、同じネットワークの中にいる？ | **大筋は正しい。** ただし「別物」なのは**機能**の話で、置く機械はルーターと同じでもよい（家庭用ルーター、labs/06 の Router VM）。ルーター自身が DHCP サーバーになるときは、LAN 側の NIC でそのネットワークに参加している |
| 1 つのネットワークに何台？ | **基本は 1 台。** 複数置くなら、配る範囲などの分担を決めておく必要がある。分担せずに 2 台いると、違うゲートウェイを配られたり、IP が衝突したりする。逆に、1 台の DHCP サーバーが複数のネットワークを担当するのは普通 |

## 質問9：DHCP はルーターの機能か

### ルーター本来の機能と、同居しているサービス

ルーターの本来の仕事は、**パケットを別のネットワークへ中継すること**（ルーティング）である。NAT とファイアウォールは、その「通り過ぎるパケット」をどう扱うかの機能である。

DHCP は、パケットを中継するのではなく、**機器に設定を配るサーバー**である。

| 機能 | 何をするか | 扱うパケット | Linux での実体 | このラボ |
|---|---|---|---|---|
| ルーティング（IP フォワーディング） | パケットを別のネットワークへ中継する | 通り過ぎるパケット | カーネル（ルーティングテーブル） | labs/02、03 |
| NAT | 中継するパケットの送信元を書き換える | 通り過ぎるパケット | カーネル（Netfilter / nftables） | labs/04 |
| ファイアウォール | 中継するパケットを通すか落とすか決める | 通り過ぎるパケット | カーネル（Netfilter / nftables） | labs/05 |
| **DHCP サーバー** | 機器に IP・ゲートウェイ・DNS を配る | **ルーターに問い合わせてくる**パケット | **普通のプログラム**（dnsmasq、Kea など） | labs/06 |
| DNS | 名前を IP に変換する問い合わせに答える | **ルーターに問い合わせてくる**パケット | 普通のプログラム（dnsmasq、Unbound など） | labs/07 |

上の 3 つは、カーネルの中で「通り過ぎるパケット」を処理する。下の 2 つは、Web サーバーと同じように「問い合わせに答える」プログラムである。

> 💡 家庭用ルーターは、ルーティング・NAT・ファイアウォール・DHCP・DNS・Wi-Fi・スイッチを 1 台に詰め合わせた箱である。だから全部が「ルーターの機能」に見える。DHCP をルーターに載せるのは、ルーターが「いつも電源が入っていて、LAN にいて、ゲートウェイ（自分）のアドレスを知っている」ので都合がよいからである。

### このラボでもすでに分かれている

[質問7](2026-10-11-what-is-vmware-nat-gateway.md) と [質問8](2026-10-11-where-to-find-dhcp-server-address.md) で確かめたとおり、VMware の中でも分かれていた。

| | IP | Windows 上のサービス |
|---|---|---|
| NAT（ゲートウェイ） | `192.168.22.2` | VMware NAT Service |
| DHCP サーバー | `192.168.22.254` | VMware DHCP Service |

IP もプログラムも別である。

### DHCP と NAT の関係

**協力はするが、別々に使える。**

| 組み合わせ | 例 |
|---|---|
| DHCP ＋ NAT（協力） | 家庭の LAN。DHCP がプライベート IP（`192.168.1.x` など）を配り、そのアドレスで外に出るときに NAT が書き換える |
| DHCP だけ | 会社の内部ネットワーク。ルーティングだけで、NAT しない区間でも DHCP は使う |
| NAT だけ | このラボの Client VM。静的 IP なので DHCP はないが、labs/04 で NAT を設定すれば外に出られるようになる |

## 質問10：DHCP サーバーはどこに置くのか

**ローカルに置く。** 正確には、**DHCP で設定をもらう機器と同じネットワーク**（ブロードキャストが届く範囲）に置く。

### 理由 1：最初の呼びかけは、ブロードキャストだから

DHCP で設定をもらう前の機器は、まだ IP アドレスを持っていない。相手（DHCP サーバー）のアドレスも知らない。だから、**同じネットワークの全員に向けて呼びかける**（ブロードキャスト）ところから始める（[DORA](../concepts/dhcp.md#dhcp-のやりとりdora) の Discover）。

```text
送信元 IP：0.0.0.0           ← 自分の IP がまだ無い
宛先 IP  ：255.255.255.255   ← 「このネットワークの全員」
宛先ポート：67               ← DHCP サーバーのポート
```

**ブロードキャストは、ルーターを越えない。** そのため、インターネット上はもちろん、ルーターの向こう側のネットワークにある DHCP サーバーにも届かない。

### 理由 2：配る中身が、そのネットワークの情報だから

DHCP が配るのは、「このネットワークで使ってよい IP」「このネットワークのゲートウェイ」など、**そのネットワークの中だけで意味のある情報**である。インターネット上のサーバーには、あなたの LAN の事情は分からない。

### このラボで実際に起きていたこと

labs/01 で、Client VM に `169.254.x.x` が付いていた。これは、Client VM の DHCP の呼びかけが VMnet2（`10.0.0.0/24`）に流れたのに、**VMnet2 には DHCP サーバーがいなかった**からである。

VMware の DHCP サーバー（`.254`）は VMnet8 側にいて、Router VM の向こう側である。ブロードキャストは Router VM を越えないので、すぐ近くにあっても届かなかった。

```text
VMnet8 ── VMware DHCP（.254）  ← ここには届かない
   │
Router VM（ブロードキャストを通さない）
   │
VMnet2 ── Client VM：「誰か IP をください」→ 誰も答えない → 169.254.x.x
```

### ネットワークごとに、DHCP サーバーがいる

DHCP サーバーは「インターネットに 1 つ」ではなく、**ネットワークごとに、そのネットワークの中に**いる。

**家庭の場合：**

```text
インターネット
    │
ISP のネットワーク ── ISP の DHCP サーバー：自宅ルーターの WAN 側に配る
    │
自宅ルーター（WAN 側：ISP からもらう ／ LAN 側：DHCP サーバーとして配る）
    │
家の LAN ── PC・スマホ：自宅ルーターからもらう
```

**このラボの場合：**

```text
VMnet8 ── VMware DHCP（.254）：Router VM の ens33 に配る      ← ISP の役
    │
Router VM（ens33：もらう側 ／ ens37：labs/06 で配る側になる）  ← 自宅ルーターの役
    │
VMnet2 ── Client VM：今は静的 IP。labs/06 以降は Router VM からもらう
```

自宅ルーターの WAN 側も、ISP から設定をもらう。そのときの DHCP サーバーも、インターネットのどこかではなく、**ISP のネットワークの中**（自宅ルーターの WAN 側の、すぐ先）にいる。

> 💡 ISP によっては、WAN 側の設定を DHCP ではなく PPPoE という別の方式で配っている。日本の光回線では PPPoE もよく使われる。

### 大きなネットワークでは：DHCP リレー

会社などの大きなネットワークでは、DHCP サーバーを専用のサーバー機に 1 台だけ置き、たくさんのネットワークにまとめて配ることがある。

そのときは、各ネットワークのルーターが **DHCP リレー**を担当する。ブロードキャストの呼びかけを受け取り、DHCP サーバーへ普通の通信（ユニキャスト）として転送する。

```text
ネットワーク A ─┐
ネットワーク B ─┼─ ルーター（DHCP リレー）── 会社のサーバー室の DHCP サーバー
ネットワーク C ─┘
```

この場合も、DHCP サーバーは**組織の内側**にいる。インターネット上ではない。

「ルーターと DHCP の関係」でいちばんルーターらしいのは、このリレーの部分である。

> 💡 DHCP には、答えてきたサーバーが本物かどうかを確かめる仕組みがない。LAN の中に偽の DHCP サーバーがいると、偽のゲートウェイを配られて通信を横取りされるおそれがある。会社のネットワークでは、スイッチの「DHCP スヌーピング」という機能で対策する。

## 質問11：理解の確認と、DHCP サーバーの台数

### 「ルーターとは別物」の意味

**機能としては別物だが、置く機械は同じでもよい。**

家庭用ルーターや、labs/06 で作る Router VM のように、ルーターと同じ機械の上で DHCP サーバーのプログラムを動かすことはよくある。「別物」というのは、「ルーティングとは別の仕事をする、別のプログラム」という意味である。

### 「同じネットワークの中」の意味

「**ルーターで区切られた 1 つのネットワークの中にいる**」という意味なら、その通りである。

```text
          ルーター（ここで区切られる）
             │ ens37：10.0.0.1
─────────────┴──────────────────  VMnet2（10.0.0.0/24）＝ 1 つのネットワーク
      │                    │
  Client VM          （DHCP サーバーはこの範囲の中にいる必要がある）
```

ルーター自身が DHCP サーバーになる場合、ルーターは「ネットワークの端」にいて、LAN 側の NIC（ens37）でそのネットワークに参加している。そのため「ネットワークの中にいる」扱いになる。labs/06 の Router VM がこの形である。

例外は [DHCP リレー](#大きなネットワークではdhcp-リレー)で、ルーターが呼びかけを転送してくれるなら、DHCP サーバーは別のネットワークにいてもよい。

### 1 つのネットワークに DHCP サーバーは何台か

**基本は 1 台である。** 複数置くこともできるが、その場合はサーバー同士で役割分担を決めておく必要がある。

**分担せずに複数いると、どうなるか**

機器は「誰か IP をください」と全員に呼びかけ、**先に答えたサーバーの設定**を使う。サーバーが 2 台いると、どちらが答えるかは運しだいになる。

| 起きること | 例 |
|---|---|
| 違うゲートウェイを配られる | 一部の機器だけインターネットにつながらない |
| 同じ IP が 2 台に配られる | 2 つのサーバーの配る範囲が重なっていると、IP が衝突する |

> 💡 家庭でよくあるトラブルが、「ルーターを 2 台つないだら、一部の端末だけネットにつながらなくなった」である。2 台目のルーターも DHCP サーバーとして配ってしまうのが原因である。2 台目を「ブリッジモード」や「アクセスポイントモード」にして、DHCP を止めると直る。

**複数置くのはどんなときか**

会社などで、DHCP サーバーが止まると困る場合である。

- 配る範囲を分けておく（例：1 台目が `.100`〜`.199`、2 台目が `.200`〜`.249`）
- サーバー同士が連絡を取り合う仕組み（フェイルオーバー）を使う

**逆に、1 台で複数のネットワークに配るのは普通である**

LAN 側の NIC が複数あるルーターや、DHCP リレーを使う会社のネットワークでは、DHCP サーバー 1 台が複数のネットワークに配る。

| 向き | 考え方 |
|---|---|
| 1 つのネットワークから見て | **配る元は 1 つ**（または、分担を決めた複数） |
| 1 台の DHCP サーバーから見て | **複数のネットワークを担当できる** |

### このラボでは

| ネットワーク | DHCP サーバー |
|---|---|
| VMnet8（`192.168.22.0/24`） | 1 台（VMware DHCP、`.254`） |
| VMnet2（`10.0.0.0/24`） | 0 台（だから Client VM に `169.254.x.x` が付いた）。labs/06 で Router VM が担当して 1 台になる |

## ルーターを自作するときの参考

[router-boundary.md](../architecture/router-boundary.md) でも、DHCP は「DHCP / DNS（必要に応じて）」と、ほかの機能とは別の行になっている。

| 観点 | 考えること |
|---|---|
| **別の部品として考える** | ルーティング・NAT・ファイアウォールは、自作ソフトから Netlink や nftables でカーネルに設定する。DHCP は、UDP 67 番ポートで待ち受ける**独立したプログラム**である。[routerd のイメージ](../../src/routerd/README.md)にはまだ DHCP が入っていない。DHCP を routerd に含めるか、別プログラム（既存ソフトでも自作でも）にするかは、今後の設計判断になる（ADR の候補） |
| **LAN 側だけで配る** | DHCP サーバーは ens37（LAN 側）だけで待ち受ける。ens33（WAN 側、VMnet8）でも配ると、VMnet8 に DHCP サーバーが 2 台いる状態になり、VMware の DHCP サーバーと取り合いになる（質問11） |
| **ほかの機能とつながる点** | DHCP が配るゲートウェイは LAN 側の自分の IP（`10.0.0.1`）、配る範囲は LAN 側のネットワーク（`10.0.0.0/24`）の中。つまり、**インターフェースの設定から DHCP の設定が決まる**。また、ファイアウォールを作ったら、LAN 側から UDP 67 番への通信を許可する必要がある |
| **既存ソフトで仕組みを知ってから自作する** | labs/06 の方針どおり。**dnsmasq**（DHCP と DNS を 1 つでこなす。OpenWrt などの家庭用ルーター向けソフトでよく使われる）や **Kea**（ISC 製の新しい DHCP サーバー）を試す。古い `isc-dhcp-server` は開発が終了しているので、新しく使うなら Kea か dnsmasq |

## まとめ

- DHCP は、厳密には**ルーターの機能ではなく、NAT の一部でもない**。機器に設定を配る**サーバー**で、家庭用ルーターが 1 台にまとめて載せているだけ。
- ルーティング・NAT・ファイアウォールは「通り過ぎるパケット」をカーネルが処理する。DHCP・DNS は「問い合わせに答える」普通のプログラム。
- DHCP サーバーは**ローカル**（設定をもらう機器と同じネットワーク）に置く。最初の呼びかけはブロードキャストで、ルーターを越えないから。
- ネットワークごとに DHCP サーバーがいる。このラボでは、VMnet8 には VMware の DHCP サーバーがいて、VMnet2 にはまだいない（labs/06 で Router VM が担当する）。
- 「ルーターとは別物」なのは**機能**の話。DHCP サーバーをルーターと同じ機械で動かすのはよくあること。
- 1 つのネットワークに DHCP サーバーは**基本 1 台**。複数置くなら分担を決める。1 台が複数のネットワークを担当するのは普通。
- 自作するときは、DHCP を**独立した部品**として、**LAN 側だけで**動かすことを意識する。
