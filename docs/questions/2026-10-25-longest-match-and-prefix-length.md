## 疑問

Client VM で `sudo ip route add 8.8.8.8/32 via 10.0.0.99` を打つと、`ip route get 8.8.8.8` は `via 10.0.0.99`、`ip route get 8.8.4.4` は `via 10.0.0.1`（default）になった。

> **質問61**：「ロンゲストマッチ：`/32` は `/0`（default）より細かいので、こちらが優先される」というのが分からない。どういうことか？

> **質問62（追加質問）**：`8.8.8.8/32` の `32` はサブネットの数字だと思っていたが、違うのか？ この数字は、ルーティングテーブルの判断の軸を表しているということか？ 例えば `8.8.8.8/32` なら、32 ビットすべてが合っているときに `10.0.0.99` へ送る。`8.8.8.8/16` なら、最初の 16 ビットまで見て、一致したら `10.0.0.99` へ送る、という理解で合っているか？

## 結論

| 質問 | 答え |
|---|---|
| ロンゲストマッチとは？ | 宛先に当てはまる行が複数あるとき、**いちばん狭い範囲を指す行**（`/` の数字＝プレフィックス長がいちばん長い行）を選ぶ決まり。`8.8.8.8` は `/32` の行にも default（`/0`）の行にも当てはまるので、狭い `/32` が選ばれた |
| `/32` はサブネットの数字とは違う？ | **同じもの。** どちらも**プレフィックス長**で、「先頭の何ビットでネットワークを区別するか」を表す。サブネットマスク（`255.255.255.0` など）と書き方が違うだけである |
| 判断の軸を表している？ `/16` なら最初の 16 ビットを見る？ | **その通り。** ルーティングテーブルでは、プレフィックス長が「この行が当てはまる宛先の範囲」になる。ただし、書くときは見ないビットを 0 にして、`8.8.0.0/16` と書く |

## 質問61：ロンゲストマッチとは何か

### `/数字` は「範囲の広さ」

IPv4 アドレスは 32 ビットである。`/数字` は「**先頭から何ビットが一致していれば当てはまるか**」を表す。数字が大きいほど条件が厳しくなり、当てはまる範囲は狭くなる。

| 書き方 | 一致が必要なビット | 当てはまる範囲 | アドレスの数 |
|---|---|---|---|
| `8.8.8.8/32` | 32 ビットすべて | `8.8.8.8` の **1 個だけ** | 1 |
| `10.0.0.0/24` | 先頭の 24 ビット | `10.0.0.0`〜`10.0.0.255` | 256 |
| `default`（＝ `0.0.0.0/0`） | 0 ビット（何も一致しなくてよい） | **すべてのアドレス** | 約 43 億 |

`default` は `/0`、つまり条件が何も無いので、どんな宛先にも当てはまる。

### 今回の結果に当てはめる

```text
default via 10.0.0.1 dev ens33 onlink            ← /0 ：すべて
8.8.8.8 via 10.0.0.99 dev ens33                  ← /32：8.8.8.8 だけ（/32 は表示で省略される）
10.0.0.0/24 dev ens33 proto kernel ...           ← /24：10.0.0.0〜10.0.0.255
```

| 宛先 | `/32`（`8.8.8.8` だけ） | `/24`（`10.0.0.x`） | `/0`（すべて） | 選ばれた行 |
|---|---|---|---|---|
| `8.8.8.8` | **当てはまる** | 当てはまらない | 当てはまる | `/32` → `via 10.0.0.99` |
| `8.8.4.4` | 当てはまらない | 当てはまらない | 当てはまる | `/0` → `via 10.0.0.1` |

`8.8.8.8` は、`/32` の行と default の行の**両方に当てはまる**。そのうち、より狭い範囲を指す（プレフィックス長が長い）`/32` が選ばれた。だから「ロンゲスト（いちばん長い）マッチ」と呼ぶ。

### たとえ：荷物の仕分け

```text
① 全国どこでも                → トラック A で送る   （default、/0）
② 東京都千代田区丸の内 1-1-1  → バイク便 B で送る   （/32）
```

丸の内 1-1-1 宛ての荷物は、①にも②にも当てはまる。この場合、**より詳しく宛先を指定した②に従う**のが自然である。詳しく書いてあるのは「ここだけは特別に扱ってほしい」という意味だからである。①は「ほかに指示が無いときの決まり」として働く。

ルーティングテーブルも同じで、細かい行は「この宛先だけは特別にこう送る」、default は「ほかのどの行にも当てはまらなかったときの送り先」である。

## 質問62：`/32` の数字はサブネットと同じものか

### 同じ `/数字` を、2 つの場面で使っている

`/数字` は**プレフィックス長**で、どちらの場面でも「**先頭の何ビットでネットワークを区別するか**」を表す。

| 場面 | 例 | `/数字` の使われ方 |
|---|---|---|
| NIC に IP アドレスを設定する | `10.0.0.10/24` | 自分と**同じネットワーク**の範囲（`10.0.0.0`〜`10.0.0.255`）。この範囲の相手には直接送る |
| ルーティングテーブルの行 | `8.8.8.8/32 via 10.0.0.99` | この行が**当てはまる宛先**の範囲 |

サブネットマスクで書くと、`/24` は `255.255.255.0`、`/32` は `255.255.255.255` である。書き方が違うだけで、中身は同じ。

`10.0.0.10/24` を設定すると、`10.0.0.0/24 dev ens33 proto kernel ...` の行が自動でルーティングテーブルに入る。サブネットが、そのままルーティングテーブルの行になっている。

### `/16` の例：最初の 16 ビットを見る

理解の通り、`/16` の行は、宛先の最初の 16 ビットが一致すれば当てはまる。ただし、書くときは**見ないビットを 0 にして**書く。

```bash
sudo ip route add 8.8.0.0/16 via 10.0.0.99
```

`8.8.8.8/16` と書くと、`Error: Invalid prefix for given prefix length.` のエラーになるはずである。見ないことにした後ろの 16 ビットに値が入っているのは矛盾している、という扱い。

2 進数で見ると、次のようになる。

```text
              先頭 16 ビット（見る）  後ろ 16 ビット（見ない）
8.8.0.0/16  = 00001000.00001000 . ********.********
8.8.8.8     = 00001000.00001000 . 00001000.00001000   → 当てはまる
8.8.4.4     = 00001000.00001000 . 00000100.00000100   → 当てはまる
1.1.1.1     = 00000001.00000001 . ...                 → 当てはまらない
```

`8.8.0.0/16` の行を足すと、`8.8.0.0`〜`8.8.255.255`（65,536 個）が全部 `10.0.0.99` へ送られる。今回の `/32` では `8.8.8.8` だけだった。

## まとめ

- `/数字` は**プレフィックス長**で、サブネットの数字・サブネットマスクと同じもの。「先頭の何ビットでネットワークを区別するか」を表す。
- ルーティングテーブルでは、プレフィックス長が「**この行が当てはまる宛先の範囲**」になる。数字が大きいほど範囲は狭い。`default` は `/0` で、すべての宛先に当てはまる。
- 当てはまる行が複数あれば、**いちばん狭い範囲を指す行**（プレフィックス長がいちばん長い行）が選ばれる。これが**ロンゲストマッチ**である。
- 行を書くときは、見ないビットを 0 にする（`8.8.8.8/16` ではなく `8.8.0.0/16`）。
