# `ip addr del` でアドレスを消すと、何が消えるのか

調査日：2026-10-11

## 疑問

> **質問6（追加質問）**：`ip addr del` でアドレスを消すと、ルーティングテーブルが削除されるだけで、インターフェースの設定は消えないのか？ネットワークは届かなくなるのか？

## 結論

| 質問 | 答え |
|---|---|
| ルーティングテーブルが削除されるだけ？ | **逆。** `ip addr del` が消すのは **IP アドレスそのもの**。ルーティングテーブルの行は、その**結果として**一緒に消える |
| インターフェースの設定は消えない？ | 「設定」が何を指すかで答えが変わる。カーネル上の IP アドレスは**消える**。NIC そのもの（`ip link`）と設定ファイルは**残る** |
| ネットワークは届かなくなる？ | 最後の 1 つのアドレスを消した場合は、**届かなくなる**。2 つ目以降のアドレスを消した場合は、そのアドレス宛ての通信だけが届かなくなる |

---

## 何が消えて、何が残るか

Client VM で、ただ 1 つのアドレスを消す場合を例にする。

```bash
sudo ip addr del 10.0.0.10/24 dev ens33
```

| 対象 | ある場所 | どうなるか | 理由 |
|---|---|---|---|
| IP アドレス `10.0.0.10` | メモリ | **消える** | このコマンドが直接消すもの |
| `10.0.0.0/24 dev ens33 proto kernel ...` の行 | メモリ | **消える** | アドレスから自動で作られた行なので、アドレスと一緒に消える |
| `default via 10.0.0.1 dev ens33` の行 | メモリ | **消える**（予想） | ens33 から最後の IPv4 アドレスがなくなると、カーネルはその NIC を使う経路を片付ける |
| ens33 そのもの | — | **残る** | `ip addr del` は NIC には触らない。`ip link` で見ると UP のままで、MAC アドレスもそのまま |
| `/etc/network/interfaces` | ディスク | **残る** | `ip` コマンドはメモリ上の設定しか変えない |

### 「インターフェースの設定」の 3 つの意味

| 意味 | 確認するコマンド | `ip addr del` の後 |
|---|---|---|
| NIC そのもの | `ip link` | 残る |
| NIC に付いた IP アドレス | `ip addr` | **消える** |
| 設定ファイル | `cat /etc/network/interfaces` | 残る |

[質問4](2026-10-11-nic-name-and-multiple-ip-addresses.md#質問4nic-名とは-ens33-などのことか) で見たとおり、`ip link` と `ip addr` は扱うものが別である。`ip addr del` が変えるのは `ip addr` の側だけである。

## ネットワークは届かなくなるか

**届かなくなる。**

| 通信 | 結果 | 理由 |
|---|---|---|
| Router VM → `ping 10.0.0.10` | 応答なし（`Destination Host Unreachable`） | `10.0.0.10` を名乗る機器がいなくなった |
| Client VM → `ping 10.0.0.1` | `Network is unreachable` | `10.0.0.0/24` の行がなくなった |
| Client VM → `ping 8.8.8.8` | `Network is unreachable` | `default` の行もなくなった |

> ⚠️ SSH で Client VM に入った状態で実行すると、その場で接続が切れる。元に戻すには、VMware のコンソールから操作する必要がある。

---

## 元に戻す方法

### いちばん簡単：再起動する

```bash
sudo reboot
```

設定ファイルは残っているので、起動時に元どおり作り直される（[質問3](2026-10-11-what-is-ip-route-and-routing-table.md#質問3ルーティングテーブルは永続化しないのか)）。

### 手で戻す

次の 2 つが必要である。

```bash
sudo ip addr add 10.0.0.10/24 dev ens33   # 10.0.0.0/24 の行は自動で戻る
sudo ip route add default via 10.0.0.1    # default の行は自動では戻らない
```

| 行 | アドレスを付け直すと |
|---|---|
| `10.0.0.0/24 ... proto kernel` | **自動で戻る**（カーネルがアドレスから作る行だから） |
| `default via 10.0.0.1` | **戻らない**（別に指定が必要な行だから） |

経路の中にも「アドレスから自動で作られる行」と「別に指定が必要な行」がある。手で戻してみると、その違いを体感できる。

## 2 つ目のアドレスを消す場合

[質問5](2026-10-11-nic-name-and-multiple-ip-addresses.md#追加方法一時的) の実験のように、`10.0.0.20` を追加してから消す場合は、**影響はそのアドレスだけ**である。

```bash
sudo ip addr add 10.0.0.20/24 dev ens33
sudo ip addr del 10.0.0.20/24 dev ens33
```

| 対象 | どうなるか |
|---|---|
| `10.0.0.20` | 消える |
| `10.0.0.10` | 残る |
| ルーティングテーブル | **変わらない**（`10.0.0.0/24` の行は `10.0.0.10` が付いている限り残る） |
| `10.0.0.10` での通信 | そのまま続く |

`ip addr del` を安全に試すなら、こちらがよい。

## まだ試していないこと

**安全な実験（SSH のままでよい）**

| コマンド（Client VM） | 予想される結果 | 確かめられること |
|---|---|---|
| `sudo ip addr add 10.0.0.20/24 dev ens33` → `sudo ip addr del 10.0.0.20/24 dev ens33` → `ip route` | 行は変わらない | 2 つ目のアドレスを消しても、経路は変わらない |

**接続が切れる実験（VMware のコンソールから実行する）**

| コマンド（Client VM） | 予想される結果 | 確かめられること |
|---|---|---|
| `sudo ip addr del 10.0.0.10/24 dev ens33` → `ip link show ens33` | `state UP` のまま | NIC そのものは残る |
| 続けて `ip route` | 何も表示されない（2 行とも消える） | アドレスから作られた行と、`default` の行が消える |
| 続けて `ping -c 2 10.0.0.1` | `Network is unreachable` | 経路が無いと、送り出すことすらできない |
| 続けて `sudo ip addr add 10.0.0.10/24 dev ens33` → `ip route` | `10.0.0.0/24` の行だけ戻る | `default` の行は自動では戻らない |
| 続けて `sudo reboot` → `ip route` | 2 行とも戻る | 設定ファイルから作り直される |

---

## まとめ

- `ip addr del` が消すのは **IP アドレスそのもの**。ルーティングテーブルの行は、その**結果として**消える。
- **NIC そのもの（`ip link`）と設定ファイルは残る。** 変わるのはメモリ上のアドレスと経路だけなので、再起動すれば元に戻る。
- 最後の 1 つのアドレスを消すと、**通信できなくなる**。SSH で入っているなら接続も切れる。
- アドレスを付け直すと `proto kernel` の行は自動で戻るが、**`default` の行は戻らない**。
- 2 つ目以降のアドレスを消すだけなら、**影響はそのアドレスだけ**。
