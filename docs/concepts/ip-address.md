# IP Address

## ネットワーク部とホスト部

IPv4 アドレスは、0 と 1 が 32 個並んだもの（32 ビット）です。それを 8 ビットずつ 4 つに区切り、`10.0.0.1` のように 10 進数で書いています。

IP アドレスは、2 つの部分に分かれます。

| 部分 | 意味 | マンションでいうと | `10.0.0.1/24` では |
|---|---|---|---|
| **ネットワーク部** | どのネットワークか | マンションの名前 | `10.0.0` |
| **ホスト部** | そのネットワークの中の、どの機器か | 部屋番号 | `1` |

**同じネットワーク内の相手には、ルーターを介さず直接届けられます。** 同じマンションの住人どうしなら、直接部屋を訪ねられるのと同じです。これが [デフォルトゲートウェイ](routing.md#デフォルトゲートウェイ) の話の前提になります。

### `/24` は「どこまでがネットワーク部か」

`10.0.0.1/24` の `/24` は、**先頭の 24 ビットがネットワーク部**という意味です（プレフィックス長と呼びます）。

```text
10.0.0.1/24

            ネットワーク部（先頭 24 ビット）  ホスト部（残り 8 ビット）
10.0.0.1  = 00001010.00000000.00000000 . 00000001
               10       0        0           1
```

8 ビット × 3 つなので、`/24` なら**最初の 3 つの数字がネットワーク部、最後の数字がホスト部**です。

`/` の後ろの数字が変わると、ネットワーク部とホスト部の境目も変わります。

| 長さ | ネットワーク部 | ホスト部 | アドレスの数 | 機器に付けられる数 |
|---|---|---|---|---|
| `/16` | 最初の 2 つの数字 | 最後の 2 つの数字（16 ビット） | 65,536 | 65,534 |
| `/24` | 最初の 3 つの数字 | 最後の数字（8 ビット） | 256 | 254 |
| `/25` | 最初の 3 つの数字 ＋ 最後の数字の先頭 1 ビット | 最後の数字の残り 7 ビット | 128 | 126 |

アドレスの数は「2 の（ホスト部のビット数）乗」です（`/24` なら 2⁸ = 256）。機器に付けられる数は、そこからネットワークアドレスとブロードキャストアドレスの 2 つを引いた数です（理由は [機器に付けられるアドレス](#機器に付けられるアドレス) を参照。`/31` と `/32` は例外）。

### 同じことを表す、サブネットマスク

`/24` は、**サブネットマスク** `255.255.255.0` で表すこともあります。ネットワーク部を 1、ホスト部を 0 にして、10 進数で書いたものです。

```text
/24 = 11111111.11111111.11111111.00000000 = 255.255.255.0
```

DHCP が配る設定や、VMware の仮想ネットワークエディタでは、この書き方が使われています（[dhcp.md](dhcp.md#dhcp-が配るもの)）。

## ネットワークアドレス

### ホスト部がすべて 0 のアドレス

**ネットワークアドレス**は、**ネットワーク部はそのままで、ホスト部をすべて 0 にしたアドレス**です。マンションでいえば「マンションの名前」で、どの部屋のことでもありません。

```text
            ネットワーク部（そのまま）         ホスト部
10.0.0.1  = 00001010.00000000.00000000 . 00000001
                                           ↓ すべて 0 にする
10.0.0.0  = 00001010.00000000.00000000 . 00000000
```

`/24` なら、10 進数のまま「最後の数字を 0 にする」と考えれば十分です。`192.168.22.129/24` のネットワークアドレスは `192.168.22.0` です。

ネットワークアドレスに `/24` を付けた `10.0.0.0/24` で、「**`10.0.0.0`〜`10.0.0.255` の 256 個**」というネットワーク（範囲）を表します。`10.0.0.0` だけでは、どこまでが範囲なのか分かりません。

> 💡 ルーティングテーブルの `default` は `0.0.0.0/0` の別名です。`/0` はホスト部が 32 ビット全部なので、**すべてのアドレスを含む範囲**になります。

### 設定に書くためのアドレス

ネットワークアドレスは、**パケットの宛先にはしません**。マンションの名前だけを書いた手紙が、どの部屋にも届かないのと同じです。

使うのは、設定ファイルや表で「**このネットワークの全員**」をまとめて指定したいときです。

| 場面 | 書き方の例 | 意味 |
|---|---|---|
| ルーティングテーブル | `10.0.0.0/24 dev ens37` | `10.0.0.0/24` 宛ては ens37 から直接届ける |
| NAT（nftables） | `ip saddr 10.0.0.0/24 oifname "ens33" masquerade` | LAN から外へ出るパケットの送信元を、ルーターの IP に書き換える（labs/04） |
| ファイアウォール（nftables） | `ip saddr 10.0.0.0/24 accept` | LAN からの通信を許可する（labs/05） |
| DHCP サーバー（Kea） | `"subnet": "10.0.0.0/24"` | このネットワークに IP を配る（labs/06） |

※ NAT・ファイアウォール・DHCP の行は書き方の例です。

ネットワークアドレスで書けなければ、`10.0.0.1`〜`10.0.0.254` の 254 台分を 1 行ずつ書くことになります。ネットワークアドレスで書いておけば、範囲内の機器が増えても、ルールはそのままで済みます。

### 同じネットワークかどうかの判定

カーネルは、宛先の IP アドレスのホスト部を 0 にして、ルーティングテーブルのネットワークアドレスと比べます。そうして、直接届けるか、ゲートウェイに渡すかを決めています。

Router VM の場合：

| 宛先 | ホスト部を 0 にする（`/24`） | 一致する行 | 送り方 |
|---|---|---|---|
| `10.0.0.10` | `10.0.0.0` | `10.0.0.0/24` | ens37 から直接届ける |
| `192.168.22.2` | `192.168.22.0` | `192.168.22.0/24` | ens33 から直接届ける |
| `8.8.8.8` | `8.8.8.0` | どれとも一致しない | `default`（`192.168.22.2` に渡す） |

## ブロードキャストアドレス

### ホスト部がすべて 1 のアドレス

**ブロードキャストアドレス**は、**ホスト部をすべて 1 にしたアドレス**で、**そのネットワークの全員宛て**を表します。マンションでいえば館内放送です。

```text
10.0.0.255 = 00001010.00000000.00000000 . 11111111
```

`/24` なら、最後の数字が `255` になります。`ip a` に出る `brd 192.168.22.255` は、このアドレスです（[`ip a` の読み方](interface.md#ip-a-の読み方)）。

`10.0.0.255` を持っている機器はいません。その代わり、`10.0.0.0/24` の機器はみな「`10.0.0.255` 宛ては自分宛てでもある」として受け取ります。

### パケットを送るためのアドレス

ネットワークアドレスと違い、ブロードキャストアドレスは**実際にパケットの宛先として使います**。IP で通信するプログラムが、**同じネットワークの全員にまとめてパケットを送るため**のアドレスです。

- **相手の IP アドレスが分からない**とき（「〇〇の人はいますか？」と呼びかけて探す）
- **全員に知らせたい**とき

全員が受け取りますが、処理するのは、そのポートで待っているプログラムがある機器だけです。それ以外の機器では、カーネルが捨てます。返事をするかどうかも、各機器しだいです。

### 使われる場面

| 目的 | 例 | 何をしているか |
|---|---|---|
| 探す | **DHCP** | 「DHCP サーバーはいますか？ IP アドレスをください」（宛先は `255.255.255.255`） |
| 探す | **Windows の名前解決（NetBIOS）** | 「〇〇という名前の PC はいますか？」（宛先は `10.0.0.255` のような、ネットワークのブロードキャストアドレス） |
| 探す | **LAN のゲームやアプリ** | 同じ LAN にいる対戦相手や、同期の相手を探す |
| 起こす | **Wake-on-LAN** | 電源の切れた PC を起こす合図を送る。電源の切れた PC は ARP に答えられないので、全員に送る。合図の中に書かれた MAC アドレスの PC だけが起きる |
| 知らせる | **RIP バージョン 1**（古い経路制御の仕組み） | 「自分はこのネットワークに行けます」と、まわりのルーターに知らせる |

どれも、**相手の IP アドレスを知らなくても、同じネットワークの中なら届く**という性質を使っています。

このラボでも使われています。Router VM の ens33 は、起動のたびに DHCP で設定をもらっていて、そのとき dhcpcd が `255.255.255.255` 宛てに呼びかけています。

ブロードキャストで送れるのは、UDP などの「1 回送るだけ」の通信です。TCP は 1 対 1 で接続を作る仕組みなので、全員宛てには使えません。

### `255.255.255.255`（限定ブロードキャスト）

IP のブロードキャストアドレスには、もう 1 つ `255.255.255.255` があります。

| アドレス | 届く範囲 | 使う場面 |
|---|---|---|
| `10.0.0.255`（ネットワークのブロードキャストアドレス） | `10.0.0.0/24` の全員 | 自分のネットワークが分かっているとき |
| `255.255.255.255`（限定ブロードキャスト） | 今つながっているケーブルの全員 | **自分のネットワークがまだ分からない**とき |

DHCP の最初の呼びかけ（Discover）は `255.255.255.255` 宛てです。IP アドレスをもらう前の機器は、自分がどのネットワークにいるのかを知らないので、`10.0.0.255` を計算できないからです（[dhcp.md](dhcp.md#dhcp-のやりとりdora)）。

### ルーターを越えない

ブロードキャストが届くのは、**同じネットワークの中だけ**です。ルーターは、ブロードキャストを反対側のネットワークへ転送しません。

> ⚠️ 外から `10.0.0.255` 宛ての `ping` を LAN に通してしまうと、全員の返事が一度に相手へ返り、攻撃に使われます（Smurf 攻撃）。そのためルーターは、初期設定ではこれを転送しません。Linux も、ブロードキャスト宛ての `ping` には初期設定で返事をしません。

### IP と MAC のブロードキャストアドレス

ブロードキャストアドレスは、IP と MAC の 2 つの層にあります。

| | IP のブロードキャストアドレス | MAC のブロードキャストアドレス |
|---|---|---|
| 値 | `10.0.0.255`、`255.255.255.255` | `ff:ff:ff:ff:ff:ff` |
| ネットワークごとに違う？ | **違う**（ネットワークアドレスと `/24` で決まる。`255.255.255.255` は除く） | **いつも同じ** |
| 書かれる場所 | IP パケットの宛先 | イーサネットフレームの宛先 |
| 表示される場所 | `ip a` の `inet ... brd 192.168.22.255` | `ip link` の `link/ether ... brd ff:ff:ff:ff:ff:ff` |
| 使う例 | DHCP、NetBIOS、Wake-on-LAN | ARP の問い合わせ。IP のブロードキャストをケーブルに流すとき |

> 💡 ネットワークアドレスと対になって出てくる「ブロードキャストアドレス」（`ip a` の `brd 10.0.0.255` など）は、**IP のほう**を指します。ARP の話をするときは「**MAC の**ブロードキャストアドレス」と付けて言うと、取り違えずに済みます。

### なぜ IP のブロードキャストがあるのか

**プログラムが話しているのは IP だから**です。

DHCP クライアントや Windows の名前解決などのプログラムは、IP と UDP で通信します。イーサネットのフレームを直接組み立てているわけではありません（直接組み立てるには、特別な権限と手間が必要です）。そのためプログラムには、IP の言葉で「全員に送って」と頼む方法が必要です。それが IP のブロードキャストアドレスです。

頼まれたあとは、カーネルが MAC のブロードキャストに変換して送ります。

```text
プログラム（例：Windows の名前解決）
   │ 「10.0.0.255 の 137 番ポートに UDP で送って」
   ▼
カーネル（IP の層）
   │ 宛先がブロードキャストなので、ARP は使わない
   ▼
イーサネット
   │ ff:ff:ff:ff:ff:ff 宛てで送る
   ▼
VMnet2 の全員が受け取る
   → 137 番ポートで待っているプログラムがある機器だけが処理する
   → それ以外の機器は、カーネルが捨てる
```

ARP は最初からイーサネットの上で動く仕組みなので、MAC のブロードキャストを直接使えます。IP の上で動くプログラムには、IP のブロードキャストが必要です。

> 💡 IP はイーサネット専用ではなく、Wi-Fi などでも同じように使えます。プログラムは「`10.0.0.255` に送る」とだけ頼めばよく、その先の「全員宛て」への変換はカーネルが担当します。

### 何が分からないかで、使うものが変わる

IP のブロードキャストと ARP は、どちらも「全員に呼びかける」仕組みですが、**分からないものが違います**。

| | IP のブロードキャスト（`10.0.0.255`） | ARP（`ff:ff:ff:ff:ff:ff` 宛て） |
|---|---|---|
| 分かっているもの | 自分のネットワーク | **相手の IP アドレス** |
| 分からないもの | **相手の IP アドレス**（誰がいるのか、どれが目的の相手か） | 相手の MAC アドレス |
| 何をするか | 全員に呼びかけて相手を探す。または、全員に知らせる | 「この IP の人の MAC アドレスは？」と聞く |
| 例 | 「〇〇という名前の PC はいますか？」（NetBIOS） | 「`10.0.0.1` の MAC アドレスは？」 |

**MAC アドレスを探すのは ARP の仕事**で、IP のブロードキャストの仕事ではありません。ARP の流れは [neighbor.md](neighbor.md#なぜ必要か) を参照してください。

実際、`10.0.0.255` 宛てに送るときは、**ARP そのものを使いません**。全員宛ての MAC アドレスは `ff:ff:ff:ff:ff:ff` と決まっていて、調べる必要がないからです。

```text
10.0.0.10 宛て（1 台）
  ① ARP で「10.0.0.10 の MAC は？」と聞く   ← ここで ff:ff:ff:ff:ff:ff を使う
  ② 返ってきた MAC 宛てに送る

10.0.0.255 宛て（全員）
  ① ARP は使わない
  ② そのまま ff:ff:ff:ff:ff:ff 宛てに送る
```

### マルチキャストに置き換わりつつある

ブロードキャストには、**関係のない機器も全員、受け取って中身を確かめなければならない**という欠点があります。

そこで新しい仕組みでは、「興味のある機器だけが受け取る」宛先である**マルチキャスト**がよく使われます。

| 仕組み | 宛先 | 何をしているか |
|---|---|---|
| mDNS | `224.0.0.251` | `xxx.local` という名前の機器（プリンターなど）を探す |
| SSDP（UPnP） | `239.255.255.250` | 家庭用ルーターやテレビなどを探す |
| RIP バージョン 2 | `224.0.0.9` | RIP バージョン 1 のブロードキャストを、マルチキャストに変えた |

> 💡 IPv6 には、ブロードキャストそのものがありません。全員宛ての役目は、マルチキャストが担当します（labs/08）。

## 機器に付けられるアドレス

### `/24` では `.1`〜`.254` の 254 個

| アドレス | 役割 | 機器に付ける？ |
|---|---|---|
| `10.0.0.0` | ネットワークアドレス | 付けない |
| `10.0.0.1`〜`10.0.0.254` | 機器のアドレス | **付ける** |
| `10.0.0.255` | ブロードキャストアドレス | 付けない |

全部で 256 個のうち、両端の 2 つを除いた 254 個が機器用です。

### 特別なのは「`.0`」ではなく「ホスト部がすべて 0 / すべて 1」

`/` の後ろの数字が変わると、どのアドレスが特別かも変わります。

| ネットワーク | 範囲 | ネットワークアドレス | ブロードキャストアドレス | 機器に付けられる数 |
|---|---|---|---|---|
| `10.0.0.0/24` | `10.0.0.0`〜`10.0.0.255` | `10.0.0.0` | `10.0.0.255` | 254 |
| `10.0.0.0/16` | `10.0.0.0`〜`10.0.255.255` | `10.0.0.0` | `10.0.255.255` | 65,534 |
| `10.0.0.128/25` | `10.0.0.128`〜`10.0.0.255` | `10.0.0.128` | `10.0.0.255` | 126 |

- `/16` では、`10.0.1.0` は範囲の途中にある普通のアドレスなので、`.0` で終わっていても機器に付けられます。
- `/25` では、ネットワークアドレスは `.0` ではなく `.128` です。

このラボのネットワークはどちらも `/24` なので、「`.0` はネットワークアドレス、`.255` はブロードキャストアドレス」と考えて問題ありません。

### 例外：`/31` と `/32`

ホスト部がとても短いネットワークは、扱いが特別です。

| 長さ | ホスト部 | 扱い |
|---|---|---|
| `/32` | 0 ビット | **1 台だけ**を表す（例：`10.0.0.10/32`）。ネットワークアドレスもブロードキャストアドレスも無い |
| `/31` | 1 ビット | ルーターどうしを 1 対 1 でつなぐときに使う。2 つのアドレスを両方とも機器に付ける（RFC 3021） |

ホスト部が 1 ビット以下だと、両端の 2 つを除いたときに、機器用のアドレスが残りません。そのため、この 2 つの長さだけはルールが違います。

## 書き方の違い

| 書き方 | 意味 | 使う場面 |
|---|---|---|
| `10.0.0.0` | ネットワークアドレス（ネットワークの名前） | 「このネットワークの名前は？」と言うとき |
| `10.0.0.0/24` | ネットワーク（`10.0.0.0`〜`10.0.0.255` の範囲） | ルーティングテーブルの宛先、NAT・ファイアウォール・DHCP の設定 |
| `10.0.0.1/24` | 機器のアドレス `10.0.0.1`。`/24` は「`10.0.0.0/24` のネットワークに属している」という意味 | NIC にアドレスを付けるとき（`ip addr add`、`/etc/network/interfaces` の `address`） |

機器にアドレスを付けるときは、`/24` も一緒に書きます。`ip addr add` で付け忘れると、`/32`（自分 1 台だけのネットワーク）として付いてしまいます。

ふだんの会話では、`10.0.0.0/24` のこともネットワークアドレスと呼ぶことが多いです。

## このラボのネットワーク

| ネットワーク | どこ | ネットワークアドレス | ブロードキャストアドレス | 主な機器 |
|---|---|---|---|---|
| `10.0.0.0/24` | VMnet2（LAN 側） | `10.0.0.0` | `10.0.0.255` | Router VM の ens37（`10.0.0.1`）、Client VM（`10.0.0.10`） |
| `192.168.22.0/24` | VMnet8（WAN 側） | `192.168.22.0` | `192.168.22.255` | Router VM の ens33（`192.168.22.129`）、VMware NAT（`192.168.22.2`）、VMware の DHCP サーバー（`192.168.22.254`） |

Router VM は 2 つのネットワークにつながっているので、ルーティングテーブルにもネットワークごとに 1 行ずつ出ます（2026-10-11 の実行結果より抜粋）。

```text
10.0.0.0/24 dev ens37 proto kernel scope link src 10.0.0.1
192.168.22.0/24 dev ens33 proto dhcp scope link src 192.168.22.129 metric 1002
```

**ネットワークが 1 つ増えるごとに、ネットワークアドレスも 1 つ増えます。** VLAN などでネットワークを増やすと（labs/09）、この行も増えていきます。
