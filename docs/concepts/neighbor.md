# Neighbor Table（近隣テーブル）

## 近隣テーブルとは

**同じネットワークにいる相手の、IP アドレスと MAC アドレスの対応表**です。IPv4 では **ARP テーブル**とも呼びます。

### なぜ必要か

同じネットワークの中でパケットを実際に運ぶのは Ethernet で、Ethernet は **MAC アドレス**で相手を指定します。IP アドレスしか知らないと、送ることができません。

そこで「この IP アドレスの機器の MAC アドレスは何か」を調べて、覚えておきます。調べる仕組みを **ARP** といいます。

```text
自分 →（全員へ）「10.0.0.1 の人、MAC アドレスを教えて」
10.0.0.1 → 自分「私です。MAC は 00:0c:29:73:2d:6b」
自分：この答えを近隣テーブルに覚えておく
```

近隣テーブルは**設定するものではなく、通信すると自動でできる**ものです。ルーティングテーブルと同じくメモリ上にあり、再起動すると消えます。

### ルーティングテーブルとの役割分担

| | ルーティングテーブル（`ip route`） | 近隣テーブル（`ip neigh`） |
|---|---|---|
| 答えること | **次に誰に渡すか**（IP アドレス） | **その相手の MAC アドレスは何か** |
| Router VM の例 | `8.8.8.8` は `192.168.22.2` に渡す | `192.168.22.2` の MAC は `00:50:56:f9:12:3d` |

パケットを送るときは、この 2 つを順番に使います。

```text
宛先 8.8.8.8
    ↓ ルーティングテーブル：次に渡す相手は 192.168.22.2（ens33 から）
    ↓ 近隣テーブル：192.168.22.2 の MAC は 00:50:56:f9:12:3d
その MAC 宛てに送る（IP の宛先は 8.8.8.8 のまま）
```

**近隣テーブルに載るのは、同じネットワークにいて、最近通信した相手だけ**です。`8.8.8.8` のような外の宛先は載りません。

> 💡 [routing.md](routing.md#たとえ) の会社のたとえでいうと、ルーティングテーブルは「社外宛ての書類は発送窓口へ」というルールです。近隣テーブルは「発送窓口は何階のどの席か」を書いた座席表です。

## `ip neigh` の読み方

```bash
ip neigh      # ip n と省略できる
```

Router VM での出力例（2026-10-11）：

```text
192.168.22.2 dev ens33 lladdr 00:50:56:f9:12:3d STALE
192.168.22.1 dev ens33 lladdr 00:50:56:c0:00:08 REACHABLE
10.0.0.10 dev ens37 lladdr 00:0c:29:20:6c:ff STALE
192.168.22.254 dev ens33 lladdr 00:50:56:fe:ec:fe STALE
```

### 1 行の読み方

```text
192.168.22.2  dev ens33  lladdr 00:50:56:f9:12:3d  STALE
  相手の IP   見えている NIC   相手の MAC アドレス    状態
```

| 部分 | 意味 |
|---|---|
| `192.168.22.2` | 相手の IP アドレス |
| `dev ens33` | その相手が見えている NIC |
| `lladdr 00:50:56:f9:12:3d` | 相手の MAC アドレス（`lladdr` は link layer address の略） |
| `STALE` など | 状態（下の表） |

### 状態

| 状態 | 意味 | 気にする必要は？ |
|---|---|---|
| `REACHABLE` | 最近、通信できることを確認済み | なし |
| `STALE` | MAC は覚えているが、しばらく確認していない。次に使うときに確認し直す | **なし（よくある状態）** |
| `DELAY` | `STALE` の相手にパケットを送ったばかりで、通信できているかの確認を少し待っている | なし |
| `PROBE` | ARP で確認し直している最中 | なし |
| `INCOMPLETE` | ARP で問い合わせたが、まだ答えが来ていない | 続くなら注意 |
| `FAILED` | ARP で問い合わせたが、答えが来なかった | **あり**（相手がいない、つながっていない） |
| `PERMANENT` | 手で固定した行。期限で変わらない | — |

状態は、時間と通信に合わせて次のように移り変わります。

```text
INCOMPLETE（問い合わせ中）
    ↓ 答えが来た                  （答えが来なければ FAILED）
REACHABLE（確認済み）
    ↓ しばらく通信しない（数十秒）
STALE（覚えているが、未確認）
    ↓ この相手にパケットを送った
DELAY（確認を少し待つ）
    ↓ 相手からの返事の通信があった → REACHABLE に戻る
    ↓ 何も無かった
PROBE（ARP で確認し直す）
    ↓ 答えが来た → REACHABLE    （答えが来なければ FAILED）
```

> 💡 **`STALE` は異常ではありません。** 「しばらく話していない相手」というだけです。トラブル調査で見るべきなのは `FAILED` や、ずっと続く `INCOMPLETE` です。たとえば、存在しない `10.0.0.99` に `ping` すると、`Destination Host Unreachable` になります。そのとき `ip neigh` には `10.0.0.99 dev ens33 FAILED` のような行が出ます（ARP に誰も答えなかった印）。

### MAC アドレスの先頭で、相手の種類が分かる

MAC アドレスの先頭 3 つ（`00:0c:29` など）は、メーカーごとの番号です。

| 先頭 | 意味 | このラボでの例 |
|---|---|---|
| `00:0c:29` | VMware が VM の NIC に自動で付ける MAC | Router VM、Client VM の NIC |
| `00:50:56` | VMware が用意した仮想機器 | VMware NAT、DHCP サーバー、Windows 側のアダプタ |

`00:50:56:c0:00:08` のように `00:50:56:c0:00:` で始まるのは、Windows 側のアダプタです。末尾の `08` は VMnet8 を表します。

## このラボで見える相手

### Router VM

| IP | NIC | 相手 |
|---|---|---|
| `192.168.22.1` | ens33 | Windows（VMware Network Adapter VMnet8）。SSH の接続元 |
| `192.168.22.2` | ens33 | VMware NAT（Router VM のデフォルトゲートウェイ） |
| `192.168.22.254` | ens33 | VMware の DHCP サーバー（推定。VMware の NAT ネットワークでは通常 `.254`） |
| `10.0.0.10` | ens37 | Client VM |

### Client VM

| IP | NIC | 相手 |
|---|---|---|
| `10.0.0.1` | ens33 | Router VM の ens37（Client VM のデフォルトゲートウェイ） |

Client VM には NIC が 1 つしかなく、同じネットワークにいる相手は Router VM だけです。

実際に観察した結果と、そのときの状態の考察は [labs/01-network-interface](../../labs/01-network-interface/README.md#5-近隣テーブルの観察router-vm--client-vm-1) を参照。
