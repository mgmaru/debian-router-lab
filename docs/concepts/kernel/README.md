## カーネルとは

### OS の中心にあるプログラム

**カーネル（kernel）は、OS の中心で動いている特別なプログラム**です。Debian などの Linux の OS では、Linux カーネルがこれに当たります。

カーネルの仕事は、パソコンの部品（ハードウェア）を管理し、ほかのプログラムが使えるようにすることです。

| カーネルが管理しているもの | 例 |
|---|---|
| CPU | どのプログラムを、いつ動かすか |
| メモリ | どのプログラムに、どれだけ使わせるか |
| NIC などの機器 | NIC ドライバーを通して、パケットを送ったり受け取ったりする |
| **ネットワークの処理** | TCP/IP、ルーティング、IP フォワード、Netfilter（NAT・ファイアウォール） |

ルーターとしての働き（パケットを受け取る・行き先を決める・書き換える・送り出す）は、**すべてカーネルの中で行われています**。

### カーネル空間とユーザー空間

Linux では、プログラムが動く場所が2つに分かれています。

```text
 ┌─────────────────────────────────────────────────────┐
 │ ユーザー空間（ふだん使うプログラムが動く場所）           │
 │                                                     │
 │   ip    nft    ping    sshd    apt    routerd（将来） │
 └──────────────────────┬──────────────────────────────┘
                        │ 「こうして」と頼む（Netlink など）
 ┌──────────────────────▼──────────────────────────────┐
 │ カーネル空間（カーネルが動く場所）                       │
 │                                                     │
 │   ルーティングテーブル   Netfilter / conntrack         │
 │   TCP/IP の処理         NIC ドライバー                 │
 └──────────────────────┬──────────────────────────────┘
                        │
                   NIC（ハードウェア）
```

| | ユーザー空間 | カーネル空間 |
|---|---|---|
| 動いているもの | `ip`、`nft`、`ping`、`sshd` など、コマンドやサービス | カーネル |
| パケットに直接触れるか | 触れない | **触れる** |
| ハードウェアを直接扱えるか | 扱えない | **扱える** |

- `ip` や `nft` は、**ユーザー空間のコマンド**。自分ではパケットに触らず、Netlink という窓口でカーネルに「この設定にして」と頼むだけ
- 転送するパケット（Client VM から 8.8.8.8 への ping など）は、**カーネル空間の中だけで処理されて出ていく**。ユーザー空間のプログラムは、1つも関わらない。コマンドを動かしていなくても転送や NAT が続くのは、このため

### カーネルの動き方を決める3種類のもの

カーネルの動き方は、次の3種類で決まります。

| 種類 | 例 | 変える方法 | たとえ |
|---|---|---|---|
| カーネルのプログラムそのもの | 関所の場所、ロンゲストマッチのやり方、TTL を減らす処理 | カーネル自体を作り直す（このラボではやらない） | 建物そのもの |
| **設定値**（スイッチ） | `net.ipv4.ip_forward = 1` | `sysctl` | 建物の電気のスイッチ |
| **参照する表・ルール** | ルーティングテーブル、nftables のルール | `ip route`、`nft` | 建物の中に貼る案内表、検査場のチェックリスト |

このラボで操作するのは、2つ目と3つ目です。カーネルのプログラムには手を加えません。

設定値とルールの違い：

| | 設定値（`ip_forward`） | ルール（nftables） |
|---|---|---|
| 中身 | ON か OFF か、のような1つの値 | 「こういうパケットなら、こうする」の並び |
| 効き方 | カーネルの処理を、丸ごと切り替える | 関所に来たパケット1つずつを、条件で調べる |
| 空のとき | （必ず何かの値を持っている） | 素通り |

### このリポジトリの方針との関係

この区別は、[Router Boundary](../../architecture/router-boundary.md) の方針とそのまま重なります。

- **カーネルのプログラム（建物）**は作らない。既にあるものを使う
- **設定値とルール（スイッチ・チェックリスト）**を、Phase 3〜4 では人が、Phase 6 では `routerd` が操作する

`routerd` は、カーネルのプログラムを書き換えるソフトではありません。**カーネルが参照する設定値とルールを、まとめて管理するソフト**です。
