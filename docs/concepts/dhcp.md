# DHCP

## DHCP とは

DHCP（Dynamic Host Configuration Protocol）は、**ネットワークにつながった機器に、IP アドレスなどの設定を自動で配る仕組み**です。

スマホを家の Wi-Fi につないだだけで通信できるのは、家庭用ルーターが DHCP サーバーとして設定を配っているからです。このラボでは、**VMware の NAT に DHCP サーバーが内蔵されていて**、ルーター VM の ens33 はそこから設定をもらっています。

---

## DHCP が配るもの

| 配るもの | ルーター VM の ens33 の例 | 役割 | 静的 IP なら何に当たるか |
|---|---|---|---|
| IP アドレス | `192.168.22.129` | 自分の住所 | `address` |
| サブネットマスク | `255.255.255.0`（= `/24`） | どこまでが同じネットワークか | `address` の `/24` の部分 |
| **デフォルトゲートウェイ** | `192.168.22.2` | ネットワークの外への出口 | `gateway` |
| DNS サーバー | `192.168.22.2` など | `google.com` のような名前を IP に変換する相手 | `/etc/resolv.conf` |
| リース時間 | 30 分など | その IP を使ってよい期限 | （なし。静的 IP は無期限） |

このほかにも、ドメイン名・NTP サーバー（時刻合わせ）・ネットワークブート用のサーバーなどを「オプション」として配れますが、家庭や VM 環境で使われるのはほぼ上の表の範囲です。

### 「DHCP」と「静的 IP」で何を自分で書くか

| NIC の設定方式 | IP アドレス | デフォルトゲートウェイ | DNS |
|---|---|---|---|
| `inet dhcp` | 自動でもらえる | 自動でもらえる | 自動でもらえる |
| `inet static` | `address` で自分で書く | 必要なら `gateway` で自分で書く | 必要なら自分で書く |

> 💡 クライアント VM はまだ DNS を書いていないので、このままだと名前解決ができません（[labs/07-dns](../../labs/07-dns/README.md)）。

## DHCP のやりとり（DORA）

つないだばかりの機器はまだ IP を持っていないので、相手を指定せずにネットワーク全体へ呼びかける（ブロードキャスト）ところから始まります。

```
クライアント → 全体:     「誰か IP をください」          (Discover)
サーバー → クライアント: 「192.168.22.129 はどう？」     (Offer)
クライアント → 全体:     「192.168.22.129 をもらいます」 (Request)
サーバー → クライアント: 「どうぞ。期限は○分」          (Ack)
```

頭文字を取って **DORA** と呼ばれます。

### 1 回目の問い合わせ

初めてつないだ機器のやりとりの、送信元と宛先は次のとおりです。上と同じく、ルーター VM の ens33 が DHCP サーバー（`192.168.22.254`）から `192.168.22.129` をもらう例です。

| ステップ | 送る側 | 送信元 | 宛先 | 理由 |
|---|---|---|---|---|
| Discover | クライアント | `0.0.0.0` | **全員（`255.255.255.255`）** | まだ IP が無い。DHCP サーバーのアドレスも、自分のネットワークも分からない |
| Offer | サーバー | `192.168.22.254` | 全員（`255.255.255.255`）、またはクライアントへ直接 | クライアントはまだ IP を使えないので、返し方を工夫する（下の 💡） |
| Request | クライアント | `0.0.0.0` | **全員（`255.255.255.255`）** | まだ IP を正式にもらっていない。DHCP サーバーが複数いるときに、どの提案を選んだかをほかのサーバーにも知らせる |
| Ack | サーバー | `192.168.22.254` | 全員（`255.255.255.255`）、またはクライアントへ直接 | Offer と同じ |

クライアントが送る Discover と Request は、どちらも**送信元 `0.0.0.0`、宛先 `255.255.255.255`** です。IP を持たない機器を、サーバーはメッセージの中に書かれた **MAC アドレス**で見分けます。

> 💡 サーバーからの返事の宛先は、クライアントがメッセージに付けた「返事は全員宛てで」という印（ブロードキャストフラグ）で決まります。印があれば `255.255.255.255` 宛て、無ければ配る IP（`192.168.22.129`）とクライアントの MAC アドレス宛てに直接送ります。

### 2 回目以降の問い合わせ

DHCP でもらった IP には期限（リース）があります。機器は期限が切れる前に、DHCP サーバーへ延長を申し込みます。最初の Ack で DHCP サーバーのアドレスが分かっているので、2 回目以降は**サーバーに直接**問い合わせます。

ルーター VM の ens33（リース 30 分）の場合：

| いつ | 何をする | 宛先 |
|---|---|---|
| 半分（900 秒）が過ぎたとき | **延長**：「引き続き使わせて」 | **DHCP サーバーに直接**（`192.168.22.254`） |
| 87.5%（1,575 秒）が過ぎても延長できないとき | **再取得**：「どのサーバーでもいいので延ばして」 | 全員（`255.255.255.255`） |
| 期限が切れたとき | IP を手放して、Discover からやり直す | 全員（`255.255.255.255`） |
| 再起動したとき | 「前の IP をまた使いたい」 | 全員（`255.255.255.255`） |

全員宛てに送るのは、同じネットワークにいるか分からないときや、前のサーバーが応答しないときなど、状況が不確かなときだけです。そのときは、どのネットワークにいても届く `255.255.255.255` を使います。DHCP が `10.0.0.255` のような、ネットワークのブロードキャストアドレスを使うことはありません。

## `ip a` などに出る DHCP の痕跡

| 見えていたもの | 意味 |
|---|---|
| ルーター VM の ens33 の `dynamic` | DHCP で借りているアドレス |
| `valid_lft 1618sec` | リースの残り時間。期限が近づくと自動で延長を申請するので、普段は切れない |
| クライアント VM の `169.254.x.x` | DHCP で問い合わせたが、10.0.0.0/24 には DHCP サーバーがいなかったため誰も答えず、自分で付けたアドレス（リンクローカルアドレス。[interface.md](interface.md) を参照） |
| 設定ファイルの `iface ens33 inet dhcp` | 「この NIC は DHCP で設定をもらう」という指定 |

## DHCP で実際に何を受け取ったかを確認する

Debian 13 で DHCP クライアントに dhcpcd が使われている場合：

```bash
sudo dhcpcd -U ens33
```

`ip_address`（IP）、`subnet_mask`（サブネットマスク）、`routers`（**デフォルトゲートウェイ**）、`domain_name_servers`（DNS）、`dhcp_lease_time`（リース時間）などが一覧で表示されます。上の表と照らし合わせると、DHCP が何を配っているのかを実感できます。

## 静的 IP と DHCP の使い分け

| | 静的 IP | DHCP |
|---|---|---|
| 向いている機器 | ルーター、サーバーなど「決まったアドレスで呼ばれる」側 | PC、スマホなど「使うだけ」の側 |
| メリット | アドレスが変わらない | 設定不要。サーバーが貸出を管理するので IP の重複が起きない |
| デメリット | 台数が増えると大変。重複の事故が起きうる | アドレスが変わることがある |

ルーター VM の ens37 を静的にしたのは、クライアントから見たゲートウェイのアドレス（`10.0.0.1`）が変わると困るからです。
