# 一時的な設定と永続的な設定

Linux のネットワーク設定には 2 つの層があります。

| | 一時的な設定 | 永続的な設定 |
|---|---|---|
| どこにあるか | 動いているカーネルの中（メモリ上） | ディスク上の設定ファイル |
| 変え方 | `ip addr add`、`ip route add`、`sysctl -w` など | `/etc/network/interfaces`、`/etc/sysctl.d/` など |
| 再起動すると | **消える** | 起動時に読み込まれて**再現される** |

`ip addr add 10.0.0.1/24 dev ens37` は「今この瞬間のカーネルに IP を付ける」コマンドです。カーネルは再起動でまっさらになるので、設定も消えます。

**永続化の正体は「起動時に毎回同じコマンドを自動で実行してもらうこと」** です。設定ファイルに書いておくと、起動時に `networking` サービスがそれを読んで、手で打っていたのと同じ処理をしてくれます。

> 💡 これはネットワークに限らない Linux 全般の考え方です。カーネルパラメータ（`/etc/sysctl.d/`）、ファイアウォール（`/etc/nftables.conf`）、マウント（`/etc/fstab`）、サービスの自動起動（`systemctl enable`）なども、すべて「起動時に読まれる場所に書く」ことで永続化します。

IP アドレスを永続化した手順は [environment/debian/network.md](../../environment/debian/network.md) を参照。

## 設定ごとの永続化の場所

| 設定 | 一時的に変える | 永続化するファイル | 起動時に読むもの | 説明書 |
|---|---|---|---|---|
| IP アドレス（labs/01） | `ip addr add` | `/etc/network/interfaces` | ifupdown（`networking` サービス） | `man interfaces` |
| カーネルの設定（labs/02） | `sysctl -w` | `/etc/sysctl.d/*.conf` | `systemd-sysctl` サービス | `man sysctl.d` |
| ファイアウォール・NAT（labs/04・05） | `nft add rule` | `/etc/nftables.conf` | `nftables` サービス | `man nft` |
| サービスの自動起動 | `systemctl start` | `systemctl enable` で設定 | systemd | `man systemctl` |

どれも、「**起動時にそのファイルを読んで、設定し直してくれるもの**」がいるから永続化できます。

## カーネルの設定（`/etc/sysctl.d/`）

### 書き方

```ini
# /etc/sysctl.d/99-router.conf
# Router VM：Client VM（10.0.0.0/24）のパケットを WAN 側へ転送するため（labs/02）
net.ipv4.ip_forward = 1
```

| 決まり | 内容 |
|---|---|
| ファイル名 | **`.conf` で終わる**こと（必須）。それ以外のファイルは読まれない |
| 書式 | 1 行に 1 つ `項目名 = 値`。項目名は `sysctl` で表示される名前そのもの |
| コメント | `#` または `;` で始まる行 |

ファイルを作っただけでは、今のカーネルには反映されません。`sudo sysctl --system` で読み直し、最後に再起動して確かめます。

### 読まれる順番

設定ファイルは 4 つの場所から読まれ、次の 2 段階で処理されます。

```text
① ファイル名ごとに、どの場所のファイルを使うか決める
     同じファイル名が複数の場所にあれば、優先度の高い場所のものだけを使う
     優先度：/etc ＞ /run ＞ /usr/local/lib ＞ /usr/lib
        ↓
② 残ったファイルを、場所に関係なく「ファイル名の順」に読む
     同じ項目が複数のファイルにあれば、後から読んだ値が勝つ
```

| 場面 | 勝つもの | 決め手 |
|---|---|---|
| **同じファイル名** | `/etc` のファイル | **場所** |
| **違うファイル名で、同じ項目** | 後から読まれたファイル | **ファイル名の順** |

**「`/etc` が最後に読まれる」わけではありません。** `/etc/sysctl.d/10-mine.conf` に書いても、`/usr/lib/sysctl.d/50-pkg.conf` に同じ項目があれば、後から読まれるパッケージの値が勝ちます。

そのため、自分の設定は **`/etc/sysctl.d/` に、`99-` で始まる名前**で書きます。先頭の数字は決まりではなく、読む順番を決めるための慣習です。

読まれる順番は、次のコマンドで確かめられます。

```bash
systemd-analyze cat-config sysctl.d    # 読まれるファイルを、順番どおりに中身ごと表示する
sudo sysctl --system                   # 読み直し、読んだファイルを順に表示する
```

## 自分の設定は `/etc` に書く

Linux では、ディレクトリごとに「誰のものか」が決まっています。

```text
/usr  … OS やパッケージのもの。パッケージ管理（apt）が管理する。自分では触らない
/etc  … このマシンだけの設定。管理者が書く。パッケージの更新でも消されない
/run  … 動いている間だけのもの。再起動で消える
```

| 設定 | パッケージの標準 | 管理者の設定 |
|---|---|---|
| カーネルの設定 | `/usr/lib/sysctl.d/` | `/etc/sysctl.d/` |
| systemd のサービス | `/usr/lib/systemd/system/` | `/etc/systemd/system/` |

パッケージの設定を変えたいときも、`/usr` のファイルは直接編集しません。`/etc` に、同じ項目を後から読まれる名前で書くか、同じファイル名のファイルを作って置き換えます。

## 永続化の方法の調べ方

永続化の方法が全部まとまったサイトはありません。次の順番で調べます。

```text
① 変えたい設定は何か               例：IP アドレス
        ↓
② 起動時に、それを設定するのは誰か   例：ifupdown（networking サービス）
        ↓
③ その説明書（man ページ）を読む     例：man interfaces
```

man ページの最後のほうにある **「FILES」の節**に、読むファイルの場所が書かれています。ブラウザでは <https://manpages.debian.org/> で、Debian のバージョンに合ったものが読めます。

ネットの記事は、古い書き方（`/etc/sysctl.conf` など）や、Debian 以外の方法のことがあります。最後は手元の `man` で確かめます。

詳しい説明と例は [カーネルの設定の永続化（質問50〜54）](../questions/2026-10-25-sysctl-d-and-config-locations.md) を参照。
